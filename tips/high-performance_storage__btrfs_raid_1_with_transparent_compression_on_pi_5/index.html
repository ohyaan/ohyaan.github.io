    High-Performance Storage: Btrfs RAID 1 with Transparent Compression on Pi 5¶

    When setting up a Raspberry Pi 5 as a high-performance Network Attached Storage (NAS) or media server, data reliability is paramount. A single drive failure can lead to complete data loss.

    While traditional software RAID (mdadm) is viable, the Btrfs filesystem offers native RAID 1 (mirroring) support with massive advantages: 1. Self-Healing Data: Btrfs stores metadata and data checksums. If a block corrupts on one drive, Btrfs automatically detects it and repairs it using the healthy copy on the other drive. 2. Transparent Compression: Compresses data on-the-fly using zstd, reducing write amplification (extending SSD lifespan) and accelerating read/write speeds. 3. Instant Snapshots: Take point-in-time backups of your files instantly without copying data.

    This guide walks you through setting up two drives in a secure, self-healing Btrfs RAID 1 array on Raspberry Pi 5.

    Step 1: Prepare the Drives¶

    You will need two drives of identical size (recommended) connected to your Raspberry Pi 5. These can be NVMe SSDs via a dual M.2 HAT, or high-quality external USB 3.0 SSDs/HDDs.

    Install Btrfs system utilities: 

    1
2
    sudo apt update
sudo apt install btrfs-progs -y

    Identify your target drives: 

    1
    lsblk
    (For this guide, we assume your target drives are /dev/sdb and /dev/sdc).

    Format the drives and create the Btrfs RAID 1 filesystem. The -d raid1 flag specifies data mirroring, and -m raid1 specifies metadata mirroring: 

    1
    sudo mkfs.btrfs -L "PiStorage" -d raid1 -m raid1 /dev/sdb /dev/sdc

    Step 2: Mount with Transparent Compression¶

    We will mount the filesystem using ZSTD compression (compress-force=zstd:3). ZSTD 3 balances compression ratio and CPU usage perfectly for the BCM2712 CPU.

    Create a mount point: 

    1
    sudo mkdir -p /mnt/storage

    Mount the filesystem (you only need to mount one of the physical drives; Btrfs will automatically detect the other member drive): 

    1
    sudo mount -o compress-force=zstd:3 /dev/sdb /mnt/storage

    Verify the Btrfs filesystem status: 

    1
    sudo btrfs filesystem show /mnt/storage
    Expected Output:

    Step 3: Configure Permanent Mounting¶

    Retrieve the UUID of your new Btrfs filesystem: 

    1
    sudo blkid /dev/sdb
    (Copy the UUID="xxx" value).

    Open /etc/fstab to configure automatic mounting on boot: 

    1
    sudo nano /etc/fstab

    Add the following mount line to the bottom: 

    1
    UUID=<YOUR_UUID>  /mnt/storage  btrfs  defaults,compress-force=zstd:3,autodefrag,noatime  0  0

    Test the fstab configuration to verify there are no syntax errors: 

    1
2
3
    sudo umount /mnt/storage
sudo mount -a
df -h | grep storage

    Step 4: Managing and Recovering from Drive Failures¶

    One of the best features of Btrfs RAID 1 is the ease of drive replacement and recovery.

    1. Identify a Failed Drive¶

    If a drive fails, Btrfs will enter a degraded state. You can check the health of the devices using: 

    1
    sudo btrfs device stats /mnt/storage
    If errors (read_errors, write_errors) are greater than 0, the drive is failing.

    2. Degraded Mounting (If one drive fails to boot)¶

    If one of your drives completely dies, the system might refuse to mount the filesystem on boot. You must mount it manually in degraded mode to retrieve your data: 

    1
    sudo mount -o degraded,compress-force=zstd:3 /dev/sdb /mnt/storage

    3. Replacing a Failed Drive¶

    Insert your new replacement drive (e.g., /dev/sdd). Run the Btrfs replace command to copy the data from the degraded virtual device array to the new physical drive: 

    1
2
    # syntax: btrfs replace start <failed-devid> <new-device> <mountpoint>
sudo btrfs replace start 2 /dev/sdd /mnt/storage

    Check the status of the replication process: 

    1
    sudo btrfs replace status /mnt/storage

    Step 5: Setting Up Automated Snapshots¶

    Btrfs snapshots are subvolumes that capture the exact state of files at a given second.

    Create a snapshot directory: 

    1
    sudo mkdir -p /mnt/storage/.snapshots

    Take a manual snapshot of your active storage subvolume: 

    1
    sudo btrfs subvolume snapshot /mnt/storage /mnt/storage/.snapshots/backup_2026_06_27

    To automate this, you can write a simple cron script or use tools like Snapper (sudo apt install snapper) to take hourly, daily, and weekly snapshots, allowing you to roll back files if you make accidental changes or suffer ransomware attacks.

    By adopting this Btrfs RAID 1 setup, your Raspberry Pi 5 storage server has robust hardware failure protection and maximum storage efficiency.
