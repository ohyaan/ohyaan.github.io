    Next-Gen IoT: Building a Matter Smart Home Sensor Node with Raspberry Pi Pico W¶

    For years, smart home devices have suffered from ecosystem fragmentation. Smart plugs, bulbs, and sensors were locked to specific hubs or required proprietary mobile apps. The introduction of Matter (an open-source, royalty-free connectivity standard developed by the Connectivity Standards Alliance, backed by Apple, Google, Amazon, and Samsung) solves this problem. Matter devices run locally over Wi-Fi, Ethernet, or Thread, and can connect to multiple ecosystems (Multi-Admin) concurrently.

    The Raspberry Pi Pico W is a high-efficiency microcontroller powered by the RP2040 chip and an Infineon CYW43439 wireless chip. With its low cost, low power draw, and built-in Wi-Fi, it is an ideal hardware platform for building custom, budget-friendly Matter smart home sensor nodes.

    This guide provides a comprehensive tutorial for setting up the Matter development environment for the RP2040, writing a C++ application to read sensor data, compiling the project, generating pairing QR codes, and commissioning the Pico W into Home Assistant (or Apple Home).

    1. Matter Architecture and Ecosystem Integration¶

    Matter runs on the application layer, leveraging IPv6-based network protocols (Wi-Fi or Thread) for secure local communication.

    graph TD A[Raspberry Pi Pico W] -->|Matter over Wi-Fi| B[Home Router / Access Point] B -->|IPv6 Routing| C[Matter Controller: Apple TV, HomePod, Home Assistant Yellow] C -->|Local Control| D[Smart Home App: Apple Home, Google Home]

    Key Matter Features:¶

    • Local Control: No cloud dependencies. If your internet connection drops, the local smart home system still operates.
    • Security: Device-to-device encryption with built-in Public Key Cryptography.
    • Multi-Admin: Share a single Pico W device with both Apple Home and Home Assistant at the same time.

    // main.cpp
#include <stdio.h>
#include "pico/stdlib.h"
#include "pico/cyw43_arch.h"
#include <platform/CHIPDeviceLayer.h>
#include <app-common/zap-generated/ids/Attributes.h>
#include <app-common/zap-generated/ids/Clusters.h>
#include <app/ConcreteAttributePath.h>
#include <app/clusters/temperature-measurement-server/temperature-measurement-server.h>
#include <app/clusters/relative-humidity-measurement-server/relative-humidity-measurement-server.h>

#define DHT_PIN 15

using namespace ::chip;
using namespace ::chip::DeviceLayer;

// Simple DHT22 driver stub
struct DHTData {
    int16_t temperature; // In Celsius * 100
    uint16_t humidity;   // In % * 100
};

DHTData read_dht22() {
    // Standard DHT22 reading logic
    // For demo purposes, returning dummy sensor metrics
    static int16_t t = 2200; // 22.00 C
    static uint16_t h = 5500; // 55.00 %

    // Simulate minor fluctuations
    t += (rand() % 21 - 10);
    h += (rand() % 41 - 20);

    return {t, h};
}

void DeviceEventManager(const ChipDeviceEvent * event, intptr_t arg) {
    if (event->Type == DeviceEventType::kCommissioningComplete) {
        printf("[+] Matter device successfully commissioned!\n");
    }
}

int main() {
    stdio_init_all();

    // Initialize Pico W Wi-Fi Chip
    if (cyw43_arch_init()) {
        printf("[-] Failed to initialize CYW43 Wi-Fi chip.\n");
        return -1;
    }

    printf("[*] Starting Matter Stack...\n");

    // Initialize Matter layers
    PlatformMgr().InitChipStack();
    ConnectivityMgr().SetWifiStationMode(ConnectivityManager::kWifiStationMode_Enabled);

    // Register event handler
    PlatformMgr().AddEventHandler(DeviceEventManager, 0);

    // Start Matter main loop thread
    PlatformMgr().StartEventLoopTask();

    // Main Sensor Reading Loop
    while (true) {
        // Read DHT22
        DHTData data = read_dht22();
        printf("[Sensor] Temp: %.2f C, Humid: %.2f %%\n", data.temperature / 100.0, data.humidity / 100.0);

        // Update Matter attribute values (Endpoint 1: Temp Sensor, Endpoint 2: Humidity Sensor)
        // 1. Update Temperature
        ConcreteAttributePath tempPath(1, app::Clusters::TemperatureMeasurement::Id, app::Clusters::TemperatureMeasurement::Attributes::MeasuredValue::Id);
        app::Clusters::TemperatureMeasurement::Attributes::MeasuredValue::Set(1, data.temperature);

        // 2. Update Humidity
        ConcreteAttributePath humidPath(2, app::Clusters::RelativeHumidityMeasurement::Id, app::Clusters::RelativeHumidityMeasurement::Attributes::MeasuredValue::Id);
        app::Clusters::RelativeHumidityMeasurement::Attributes::MeasuredValue::Set(2, data.humidity);

        sleep_ms(5000); // Poll sensor data every 5 seconds
    }

    return 0;
}

    5. Flashing and Commissioning (Pairing)¶

    Step 1: Flash the Pico W¶

    1. Press and hold the BOOTSEL button on the Pico W board.
    2. Connect the Pico W to your PC using a micro-USB cable.
    3. Release the BOOTSEL button. The Pico W will mount as a USB storage drive named RPI-RP2.
    4. Drag and drop pico_matter_sensor.uf2 onto the RPI-RP2 volume. The drive will automatically unmount, and the program begins execution.

    Step 2: Generate Matter Onboarding Codes¶

    Every Matter device needs unique onboarding details to pair securely. The default development values configured in the SDK are: - Discriminator: 3840 (identifies the device type during scanning) - Setup Pin Code: 20202021

    To pair the device, convert these values into a standard Matter setup payload string: 

    1
2
    # Run the helper script inside the Matter SDK directory
python3 ../connectedhomeip/scripts/tools/setup_payload/generate.py --discriminator 3840 --passcode 20202021 --vendor-id 0xFFF1 --product-id 0x8000 --commissioning-flow 0 --rendezvous 2
    This script outputs the pairing details: 
    1
2
    Manual Code: 34970112332
QR Code URL: https://project-chip.github.io/connectedhomeip/qrcode.html?data=MT%3AY.K50400%2000KA00
    Open the QR Code URL in a browser to display the Matter pairing QR code image on your screen.

    6. Pairing with Home Assistant¶

    Now add the Pico W to your Home Assistant dashboard.

    graph LR A[Home Assistant Companion App] -->|Scan QR Code| B[Pico W Bluetooth/Wi-Fi Beacon] B -->|Transfer Wi-Fi Credentials| A C[Pico W] -->|Connects to Wi-Fi| D[Home Network] D -->|Matter Protocol Exchange| E[Home Assistant Controller]

    Steps to Commission:¶

    1. Ensure your Home Assistant system has the Matter Integration enabled and configured (requires a Matter Controller like Home Assistant Yellow or a Raspberry Pi 4/5 running HA OS with a SkyConnect dongle).
    2. Open the Home Assistant Companion App on your smartphone (connected to the same local Wi-Fi network).
    3. Navigate to Settings > Devices & Services.
    4. Click Add Integration, select Add Matter Device.
    5. Scan the QR code displayed on your PC screen.
    6. The app will detect the Pico W, request permission to share your local Wi-Fi network credentials, and configure the device over Bluetooth or Wi-Fi.
    7. Once finished, you will see a new Temperature & Humidity Sensor card appear in your Home Assistant dashboard!

    7. Conclusion¶

    You now have a fully functional, open-standard Matter sensor device built on a cheap Raspberry Pi Pico W. By bypassing proprietary APIs and hubs, your sensor nodes talk directly to your home automation platform locally. Explore other clusters in the Matter SDK to build smart outlets, switches, or custom actuators!
